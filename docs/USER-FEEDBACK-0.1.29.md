# 0.1.29 使用反馈处理

本轮依据用户提供的 0.1.26 实机反馈更新，纳入 0.1.29 公开预览版。下载与发布日期见 [GitHub Release](https://github.com/AkiNariT/Markdown-Editor-Mindmap/releases/tag/v0.1.29)，实际检查范围见 [验证记录](VALIDATION-0.1.29.md)。

## 对应操作

| 反馈 | 本轮改进与入口 |
| --- | --- |
| 文件夹版静默退出 | 发布构建关闭 RunAsNode、NodeOptions；新增隔离的文件夹和单文件启动测试 |
| 连线不能选直角 | 编辑导图 → 连线 → 曲线、直角或直线；遇到节点遮挡仍尽量绕行 |
| 长标题被省略 | 按完整文本自动增高；“节点宽度”可选紧凑、标准、宽松 |
| 页面比例与图片/PDF | 导图工具栏“导出” → 格式、页面、范围 → 保存导出 |
| 折叠后手动偏移留白 | “整理布局”重排整图并清除手动偏移；支持撤销，折叠状态保留 |
| 关系线样式 | 点击关系线，直接设置说明、线型、箭头、固定颜色 |
| Markdown 大纲生成 | Markdown 页面“标题转导图”，忽略代码块和文件头中的假标题 |
| 节点副标题 | 编辑选中节点，在“备注”中输入；支持多行、保存及撤销 |
| 总览加分章 | 导出范围选择“总览与各章”；总览至二级，一级章节各自展开为一页 |

SVG、PNG 分章导出保存在同一目录并编号；PDF 保存为一个多页文件。导出使用白色页面与浅色主题，适合打印、放入幻灯片。固定比例会等比缩放并留白；很大的单章仍可能需要拆分，不会自动缩短标题或省略正文。PNG 为控制资源占用，单张最多约 1600 万像素、单边 8192 像素；矢量格式更适合大型导图。

“标题转导图”创建新的未保存导图，不改写原 Markdown。已保存的源文件会被关联到新节点；未保存草稿不生成虚构路径。导图包含标题层级，不是完整讲义正文的打包格式。

## 格式兼容

新字段使用 `.mdmap` v6，需要 MD 0.1.29 或更新程序：顶层 `lineStyle`（curve/orthogonal/straight）、`nodeSize`（compact/standard/wide）；节点 `subtitle`；关系线 `style`（solid/dashed）、`arrow`（none/end/both）、`color`（六位十六进制）。旧 v1 至 v5 导图仍可读取；新增字段要求使用 v6。保存新格式后，旧软件会明确拒绝不支持的版本。

## 启动结论的修正

反馈中“RunAsNode 开启意味着永久 Node 模式”的说法不准确。它决定是否接受 `ELECTRON_RUN_AS_NODE` 环境变量。已在旧产物中通过注入该变量复现进入 Node 模式；未取得反馈者当时的环境变量，不能据此断定其唯一根因。

当前构建使用 `resources/app`，所以不能直接照搬 `OnlyLoadAppFromAsar:true`。使用官方 fuse API 改写并回读检查，保留其他开关及应用加载方式，不依赖固定二进制偏移。

依据：[Electron fuses 官方文档](https://www.electronjs.org/docs/latest/tutorial/fuses)。实际检查结果见 [0.1.29 验证记录](VALIDATION-0.1.29.md)。
